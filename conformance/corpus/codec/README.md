# Codec Conformance Corpus

Each entry is a pair `<name>.yaml` + `<name>.bytes.hex`:

- `<name>.yaml` describes a typed protobuf message in a serde-friendly
  schema. The `kind` field tags the variant; remaining fields populate
  the message.
- `<name>.bytes.hex` is the protobuf-encoded form of that message,
  hex-encoded, no whitespace.

## Slice 1 status — regression anchor only

The `.bytes.hex` files in slice 1 are generated by encoding the YAML
inputs through this repository's own `prost`-based encoder. They serve
as a **regression anchor**: any change to the encoder that produces
different bytes triggers a test failure, forcing a deliberate review.

**They are not Go-validated.** Slice 2 (`setup-cgo-fuzz-harness`)
replaces these with bytes produced by the upstream Go reference via the
CGO oracle. Once that lands, the corpus becomes a true cross-impl
golden set.

## Regenerating the hex files

After adding or modifying a `.yaml`:

```sh
ETHP2P_REGEN_CODEC_CORPUS=1 cargo test -p ethp2p-broadcast --test conformance
```

This writes fresh `.bytes.hex` files. Inspect, commit. Subsequent runs
without the env var assert byte-equality against the committed hex.

## Adding new entries

1. Add `<name>.yaml` describing the message.
2. Run the regeneration command above.
3. Commit the new pair.
4. The conformance test discovers the pair automatically via directory
   walk.
