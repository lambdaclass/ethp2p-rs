## Context

`port-charter` Requirement 3 commits to bit-compat with the Go reference
at the protocol layer. Slice 1 delivered a Rust codec with a regression-
anchor corpus (encoder ↔ stored bytes); the bytes were generated by the
Rust encoder itself. That validates self-consistency, not cross-impl
agreement.

Slice 2 closes that gap by introducing differential fuzzing: random or
arbitrary inputs are fed to both implementations, and outputs are
compared. The Go reference is reached via a CGO `c-archive` (`libgoref.a`)
linked into the Rust fuzz binary.

The `goref/` shim is the **single exception** to clean-room (per
`port-charter` Requirement 2). The shim maintainer reads upstream Go
source to write `//export` wrappers; everyone else (including the Rust
harness author) does not. This slice splits the work explicitly across
two PRs to honor that boundary.

## Goals / Non-Goals

**Goals:**

- Stand up `cargo-fuzz` integration in a separate `fuzz/` cargo project
  excluded from the main workspace.
- Define the FFI contract precisely enough that the shim can be
  implemented from spec + README alone.
- Provide a non-FFI sanity fuzz target so the Rust-side rails can be
  verified end-to-end before the shim lands.
- Provide a feature-gated differential fuzz target that lights up when
  the shim arrives.
- Centralize all `unsafe` code in one audited FFI module; the rest of
  the workspace stays `unsafe_code = "forbid"`.
- Document the shim-maintainer role concretely in `CONTRIBUTING.md`.

**Non-Goals:**

- The actual `goref/` Go source. Authored separately by the shim
  maintainer (Pablo) in a follow-up PR.
- Fuzz CI for the differential targets. Gated on the shim PR.
- Coverage-guided corpus seeding from the slice 1 conformance corpus.
  Possible but not required for the first slice; can be added when
  fuzzing reveals corpus gaps.
- Replacing the slice 1 Rust-encoded `.bytes.hex` regression anchors
  with Go-validated golden bytes. That's a worthwhile follow-up but
  belongs to a "regen-corpus" PR after the shim lands; keeping it out
  of this slice keeps the diff focused.
- Fuzzing the engine, the strategies, or the transport. Slices 3, 4, 6.

## Decisions

### `cargo-fuzz` (libfuzzer-sys), not honggfuzz

`cargo-fuzz` is the de-facto standard, has the best ergonomics, and
ships first-class on stable Rust now. Coverage feedback comes from
sancov instrumentation, which works well with libfuzzer.

`honggfuzz-rs` is sometimes recommended for FFI-heavy targets because
honggfuzz uses different signal handling that plays nicer with non-Rust
code in the same process. We accept the small risk that libfuzzer's
signal handling will fight CGO; if it does, the fallback is to add
honggfuzz as a parallel target without ripping out cargo-fuzz.

### `fuzz/` is its own cargo project, excluded from the main workspace

`cargo-fuzz init` produces this layout by convention. The reasons:

- Fuzz targets are binaries with `panic = "abort"` and special build
  flags; intermixing them with library crates causes lock contention on
  `Cargo.lock`.
- `libfuzzer-sys` and `arbitrary` are dependencies most users do not
  want compiled when running `cargo build` from the root.
- Excluding via `[workspace] exclude = ["fuzz"]` in the root `Cargo.toml`
  + an empty `[workspace]` block in `fuzz/Cargo.toml` keeps the two
  worlds clean.

### One audited `unsafe` module; rest of the workspace stays `forbid`

The workspace lints config sets `unsafe_code = "forbid"` (slice 0).
`forbid` cannot be locally weakened by inner attributes within the same
crate. The fuzz crate is excluded from the main workspace, so it does
*not* inherit the workspace lint table; it sets its own
`unsafe_code = "deny"` (which can be `allow`-ed in specific modules).

The single audited unsafe module is `fuzz/src/ffi.rs`. It contains:

- `extern "C" { fn goref_*(...) -> ... }` declarations
- a thin wrapper per FFI function that accepts `&[u8]` and returns
  `Option<Vec<u8>>` (None = parse error)
- a single `unsafe { ... }` block per wrapper, with a comment block
  documenting the safety argument

Higher-level fuzz targets call only the safe wrappers.

### CGO `c-archive`, not `c-shared`

`-buildmode=c-archive` produces a static library `libgoref.a` plus a
`libgoref.h` header. Static linkage avoids the runtime-discovery cost
of a dynamic library and produces self-contained fuzz binaries that can
be cached by libfuzzer's persistent-mode mechanics.

`c-shared` would build a `.so`/`.dylib`. Rejected for the same reasons:
runtime discovery, `LD_LIBRARY_PATH`/`DYLD_LIBRARY_PATH` ergonomics,
and reduced libfuzzer caching.

### FFI surface: parse-and-reencode, not parse-only

For each protobuf message type we expose a single FFI function:

```c
int goref_<msg>_parse_and_reencode(
    const uint8_t* in_buf, size_t in_len,
    uint8_t** out_buf, size_t* out_len);
void goref_free(uint8_t* buf);
```

- Returns 0 on success, nonzero on parse error.
- On success, `*out_buf` is a `C.malloc`-allocated buffer of `*out_len`
  bytes containing the canonical re-encoding. The caller must call
  `goref_free` to release it.

**Why parse-and-reencode rather than parse-only?**

A parse-only FFI returns a structured Rust object representing the
parsed message. To compare with Rust's parse, we'd need to inspect every
field, which is fragile and protobuf-version-specific.

Parse-and-reencode collapses the comparison to a single byte-equality
check: both implementations parse the input, then re-encode through
their own serializer. If the inputs differ but both parse to the same
logical message and re-encode to the same bytes, equality holds. If
they diverge anywhere — different default-value handling, different
unknown-field treatment, different field ordering — equality fails.

This is the standard idiom for differential protobuf testing.

### Memory ownership: Go shim allocates via `C.malloc`, Rust frees via `goref_free`

Per `port-decisions.md` "Don't return Go-allocated memory across the
FFI boundary; copy to a Rust-owned buffer in the shim." Go's GC manages
the proto-marshal output; passing that pointer across cgo without
copying is unsafe (the GC may move or free it). The shim copies into a
`C.malloc`-allocated buffer and returns the pointer. Rust calls
`goref_free` (which the shim implements as `C.free`) when done.

The Rust safe wrapper RAII-guards this: every successful call returns
a `Vec<u8>` (a fresh Rust-owned allocation copied from the C buffer)
and immediately frees the C buffer.

### Sanity target before differential target

`fuzz/fuzz_targets/codec_decode_bcast.rs` is a non-FFI fuzz target
that feeds random bytes to `ethp2p_broadcast::wire::read_framed::<Bcast>`
and asserts no panic. This validates the cargo-fuzz pipeline before the
shim lands. It also catches Rust-side panics the slice-1 unit tests miss.

`fuzz/fuzz_targets/codec_bcast_diff.rs` is the differential target,
gated behind `--features goref-shim`. It compiles out cleanly without
the feature.

### Feature flag `goref-shim`, default off in this PR

`fuzz/Cargo.toml` declares `[features] goref-shim = []`. In this PR the
feature is undeclared as default; consumers must opt in. The follow-up
PR by Pablo flips it to `default = ["goref-shim"]`.

The build.rs `link` step is `#[cfg(feature = "goref-shim")]`-gated. So
without the feature, no linkage attempt, no missing-symbol errors.

### Shim maintainer named in CONTRIBUTING.md

This PR adds a section to `CONTRIBUTING.md` naming Pablo Deymonnaz as
the current shim maintainer. The section also documents the boundary:
the maintainer may not contribute Rust code to crates wrapping the same
protocol surface their shim exposes. Future maintainer rotations are
done by PR against `CONTRIBUTING.md`.

## Risks / Trade-offs

- **[Risk]** libfuzzer's signal handlers and Go's runtime may fight.
  Symptoms: hangs on signal, segfaults during shutdown, or corrupted
  reproducer files.
  → **Mitigation**: if observed, switch the differential target to
  `honggfuzz-rs` while keeping cargo-fuzz for non-FFI targets. Honggfuzz
  is a parallel addition, not a replacement.

- **[Risk]** Cgo cross-compilation is messy. Building `libgoref.a` for
  macOS arm64 from a Linux CI runner (or vice versa) is a known pain
  point.
  → **Mitigation**: each platform builds its own `libgoref.a` locally
  via build.rs. CI only runs the fuzz job on `ubuntu-latest`, where the
  Go toolchain is straightforward.

- **[Risk]** The shim maintainer accidentally diverges from the
  README-defined FFI surface, causing silent linkage failures or
  semantic mismatches.
  → **Mitigation**: the README is precise (function signatures,
  ownership rules, error codes). The follow-up shim PR's CI exercises
  the differential target end-to-end; a divergence shows as a fuzz
  failure within seconds.

- **[Risk]** The slice-1 `.bytes.hex` regression anchors are still
  Rust-self-consistent rather than Go-validated. They could enshrine a
  Rust bug.
  → **Mitigation**: planned regen-corpus follow-up after the shim
  lands. Until then, slice 1 corpus is "regression anchor" exactly as
  documented in its README.

- **[Trade-off]** Two PRs to land slice 2 (this one + the shim PR).
  More ceremony, but the alternative (single PR) violates clean-room.

- **[Trade-off]** Fuzz CI is initially limited (60 seconds smoke).
  Worth it to get *some* signal early; longer fuzz budgets land when
  the differential target is wired in.

## Migration Plan

This is greenfield infrastructure. No migration in the traditional
sense.

Deployment:

1. Land this change as PR #N against `main`.
2. After merge, archive (`/opsx:archive setup-cgo-fuzz-harness`) to
   promote `cgo-fuzz-harness` into `openspec/specs/`.
3. Pablo (shim maintainer) opens a follow-up PR adding `fuzz/goref/`
   Go source, flipping the default feature, and enabling differential
   CI. That PR cites this slice's archived spec.
4. After the shim PR merges, run `cargo fuzz run codec_bcast_diff` for
   a longer-duration session (e.g. 1 hour) and seed `fuzz/corpus/` from
   the slice-1 `conformance/corpus/codec/*.bytes.hex`.

Rollback: revert this PR. The fuzz directory is a leaf; nothing in
`crates/*` depends on it.

## Open Questions

- **fuzz CI runner OS**: Linux only initially. Adding macOS later is
  reasonable once the shim PR lands and confirms the Go toolchain is
  stable across runners. Not in this slice.
- **Coverage-guided corpus seeding**: cargo-fuzz can seed initial
  corpora from `corpus/<target>/`. The slice 1 conformance corpus is a
  natural seed source. Defer until first fuzz session reveals coverage
  gaps; premature seeding can mask regressions.
- **`arbitrary` derive integration**: the differential target uses raw
  `&[u8]` input; structured fuzzing via `Arbitrary` derive on the
  protobuf types would explore more of the input space. Defer to a
  later "improve fuzzing" slice; not blocking.
- **Honggfuzz fallback**: hold off until libfuzzer signal-handling
  problems are observed. Adding honggfuzz speculatively doubles the
  surface for no gain.
- **`goref_free` symbol name**: chosen so the shim and Rust agree on
  one allocator-pair entry point. If the shim ends up with multiple
  allocator categories (e.g., one per buffer type), revisit.
